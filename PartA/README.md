# PART A – PERSISTENCE DESIGN & PSEUDOCODE (25 Marks)

All Part A tasks are design submissions, not Java implementation submissions. Each task folder contains record layouts or object/table designs, SIMATS-style algorithmic pseudocode, diagrams where useful, technical reasoning and the alternative-concept/complexity analysis required by the PDF.

| Task | Deliverables |
|---|---|
| A1 | Text and binary record layouts; add/find/list pseudocode; stream justification; damaged data; RandomAccessFile comparison |
| A2 | Read-call prediction; buffered block pseudocode; `Files.readAllLines()` pseudocode; time/space analysis; buffering limitation |
| A3 | Common DAO pattern; generic `Dao<T,K>` pseudocode; StudentDao operations; field-to-column mapping |
| A4 | Hostel/Room/Resident object graph; transient-field decisions; serialization/versioning pseudocode; CSV/JSON comparison |
| A5 | JDBC transfer transaction pseudocode; PreparedStatement login pseudocode; injection and auto-commit analysis |

**No `.java` files are included under PartA**, in accordance with the assignment instruction that Java code will not be accepted in place of pseudocode.
